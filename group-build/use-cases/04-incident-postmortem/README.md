# Incident to Post-Mortem

## Business owner

Chief Information Officer

## Business problem

Incident timelines and root-cause evidence are difficult to assemble across ticket and change systems.

## Expected skill

Apply the timeline format, five-whys method and severity matrix.

## Required MCP tools

get_incident, get_change_log, create_problem_ticket

## Expected business output

Word post-mortem identifying the triggering change and a governed problem ticket.

## Build sequence

1. Review the business requirements.
2. Implement the skill.
3. Implement and validate the MCP tools.
4. Package the plugin.
5. Integrate the same MCP server with Copilot Studio.
6. Process the unseen dataset.
7. Validate the final output.
